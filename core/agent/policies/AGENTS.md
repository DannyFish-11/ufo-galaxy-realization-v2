# AGENTS.md — Agent 工作规范
#
# 本文件作为 Agent 的工作手册，规范执行流程、质量标准和工具使用方式。
# 适用于所有 Agent（单体 / Team / Swarm）的生命周期管理。

## 工作流程

### 任务接收
1. 接收用户的自然语言任务描述。
2. 解析任务意图与目标，提取关键参数。
3. 评估任务复杂度，决定使用单体 Agent、Team 还是 Swarm。

### 任务规划
1. 将复杂任务分解为有序子任务列表。
2. 标识各子任务的依赖关系。
3. 为每个子任务匹配最合适的工具或能力。
4. 生成执行计划（`agent_steps` 列表）。

### 任务执行
1. 按照执行计划逐步调用工具。
2. 每步执行后检查结果，失败时根据重试策略重试（最多 3 次）。
3. 遇到阻塞性错误立即终止并上报，不继续后续步骤。
4. 所有工具调用记录到 `tool_calls` 列表。

### 结果汇报
1. 汇总所有子任务结果为统一的 `task_result`。
2. 生成用户友好的自然语言摘要。
3. 如有后续建议，附加到响应中。

## Agent 类型选择规范

| 场景 | Agent 类型 |
|------|-----------|
| 单一明确任务 | 单体 Agent（默认） |
| 需要多模型并行验证 | PARALLEL Team |
| 多步骤专业分工任务 | SPECIALIZED Team |
| 大规模同类重复任务 | SWARM |
| 涉及多设备协同 | SPECIALIZED Team + Gateway |

## 工具调用规范

- 调用工具前验证参数类型和必填字段。
- 超时时间：MCP 工具 30s，Skill 执行 60s，设备命令 45s。
- 工具返回错误时不得伪造成功结果。
- 工具调用结果必须传递给 LLM 进行下一步决策，不得跳过。

## 质量标准

- 任务完成率 ≥ 95%（有效请求）。
- 单步工具调用超时率 ≤ 5%。
- 严禁输出包含凭据、密钥、个人身份信息的原始数据。
- 每次任务执行必须有完整的 `agent_steps` 记录。

## 错误处理规范

1. **工具不可用**：降级到替代工具，若无替代则告知用户。
2. **LLM 不可用**：使用规则引擎降级，不中断服务。
3. **设备离线**：报告设备状态，等待用户确认是否重试。
4. **权限不足**：立即停止并请求用户授权，不绕过权限检查。
