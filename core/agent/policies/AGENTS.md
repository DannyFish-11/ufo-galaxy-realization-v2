# AGENTS — Galaxy Agent 工作规范

> 本文件在 Agent 执行链路中注入，定义所有 Agent 的工作标准和行为规则。

---

## 任务接收规范

1. **任务确认**: 接收任务后，先输出执行计划（步骤列表），再开始执行
2. **步骤记录**: 每个执行步骤必须记录到 `agent_steps`，包含:
   - `step_id`: 唯一步骤标识
   - `description`: 步骤描述
   - `tool_name`: 使用的工具（若有）
   - `status`: pending / running / done / failed
   - `output`: 执行输出（done 状态时）
   - `error`: 错误信息（failed 状态时）
3. **工具限制**: 所有工具调用必须经由 `CapabilityRegistry.invoke()`，禁止硬编码绕过

---

## 工具使用规则

### 选择工具
- 从 `CapabilityRegistry.list_tools()` 中选择，不重复实现已有能力
- 工具名精确匹配，不猜测工具名称
- 若无合适工具，在 `tool_name` 填 `null`，进入 LLM 直接处理路径

### 调用规范
- 调用前检查参数完整性（必填参数不能为空）
- 工具调用失败时重试最多 **2 次**，仍失败则标记步骤为 failed 并上报

### 工具调用记录
每次工具调用记录到 `tool_calls`:
```json
{
  "tool": "工具名",
  "params": {},
  "success": true,
  "result": "...",
  "error": ""
}
```

---

## 质量标准

### 最终回复必须包含
- `reply`: 用自然语言描述的执行结果（不允许空字符串或"已完成"等无信息回复）
- `task_result`: 结构化任务结果，包含 `success` / `steps_summary` / `outputs`

### 禁止行为
- 空回复（`reply` 为空字符串）
- 伪完成（声称已完成但无任何输出）
- 硬编码绕过注册表
- 在 `agent_steps` 中忽略失败步骤

### 长任务
- 步骤数超过 3 步时，提供进度估算
- 每步完成后更新状态，不等全部完成再更新

---

## 多 Agent 协作规范

### 角色划分
- 每个 Agent 只负责分配给自己的子任务
- 子任务完成后及时更新状态，不等待其他 Agent
- 主 Agent（Orchestrator）汇总所有子任务结果后回复用户

### 通信规范
- Agent 间通过 `AgentMessageBus` 通信
- 禁止 Agent 直接操作其他 Agent 的数据结构
- 子 Agent 失败时向主 Agent 报告错误，不自行终止全局任务

### 任务分配模式
| 模式 | 适用场景 | 说明 |
|------|---------|------|
| single | 单一任务 | 一个 Agent 完成全部步骤 |
| team | 可并行子任务 | 多个 Agent 并行执行不同步骤 |
| swarm | 复杂协作任务 | 多 Agent 动态协作，有共享上下文 |

---

## 错误处理规范

### 可重试错误
- 网络超时（重试 2 次）
- 工具临时不可用（重试 1 次，间隔 1 秒）

### 不可重试错误
- 参数错误（直接标记失败，报告参数问题）
- 权限不足（直接标记失败，告知用户授权需求）
- 工具不存在（直接标记失败，列出可用替代工具）

### 部分失败处理
- 独立步骤失败时继续执行其他步骤
- 依赖步骤的前置步骤失败时跳过并标记为 skipped
- 最终结果如实反映成功/失败/部分成功状态
