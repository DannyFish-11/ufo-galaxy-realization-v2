> 本文档保留完整方案与激活条件,"没准啥时候可能用得上"。
> 背景:`/ws/master` 幻影路由的两个历史动机(算力聚合、中心可用性)拆解
> 归位后得出的四条路,经逐条评估全部搁置。

## 1. WoL 唤醒主脑

**问题**:台式机(主脑)不能保证常开;需要远程拉起。

**方案 A(已选,零开发)**:即插即用 WoL 外设 —— USB 供电小盒接电脑,
WiFi 直连,经厂商 App(米家生态)远程开/关机/重启。不接入本系统,
作为纯物理外设使用。

**方案 B(存档,若将来想收进系统)**:做成节点动作 ——
后端存台式机 MAC,暴露"唤醒主脑"动作;局域网内任一在线设备发
102 字节魔术包(UDP);需 BIOS 开 WoL + 网卡属性允许唤醒。
边界:魔术包仅局域网有效,人在外面需家内常开设备代发。

## 2. 客户端网关回退列表

**问题**:主脑关机期间,手机/手表连不上任何大脑。

**方案(存档)**:Android `GalaxyWebSocketClient` / Wear `AIPClient` 的
网关地址由单值改为有序列表 `[家, 云]`;主地址重试 N 次失败(复用
PR #509 认证状态机的重连退避)→ 切下一个;UI 如实显示"当前连接:
云端备用中心";后台低频探测主地址,活了回切。
依赖:没有选项 3 的云端中心,切换过去是空的 —— 必须成对实施。

## 3. 云端暖备中心 + 记忆单向同步

**问题**:主脑离线期间仍想要聊天/查记忆/云端执行。

**方案(存档,设计先行)**:云服务器跑同一套系统的无头形态,三段机制:

1. **平时**:家→云**单向**定期同步(unified_memory、会话主线、设备注册表)。
   单向是核心设计决策 —— 云端平时只读不写,从根上消灭双写冲突;
2. **接管期**:云端用同步来的记忆服务;做不了的事(如操作家里屏幕)
   如实拒绝(同 WearOS 诚实拒绝语义);接管期新增打"增量"标记;
3. **交还**:家中心恢复后拉回接管期增量追加合并 —— 因为只有云端在写,
   是单向追加不是双向对账。

**明确非目标**:不是双活、不是联邦。同一时刻只有一个权威中心。
**实施前置**:先出设计文档定三件事 —— 同步哪些状态、增量如何标记
与回合、云端"不能做"清单。

## 4. mesh-llm 分布式推理池

**问题**:想跑单机显存放不下的开源大模型。

**方案(存档)**:[michaelneale/mesh-llm](https://github.com/michaelneale/mesh-llm)
—— Rust + llama.cpp 魔改,QUIC 组网,多机 GPU 拼一个池;单机放得下
本地跑、peer 已加载则转发、放不下按层切流水线("skippy")。
每个节点暴露 OpenAI 兼容端点(:9337)。

**接入方式(零 v2 代码)**:提供商注册表加一条 `base_url` 指向本机
:9337,级联档位放"质量档"(本地 Ollama 与云 API 之间),bandit 自学。

**要点**:仅用私有 mesh(邀请令牌);GGUF/HF 快照;跨公网流水线首
token 延迟偏高,不适合语音实时档,须实测;项目年轻(2026-04 走红),
公网组网建议叠加 WireGuard/Tailscale。

**搁置理由**:定位为过渡产品 —— 等本地芯片能跑 120B 级(NVIDIA 方向
的桌面推理硬件)或出现即插即用的开源大模型方案,此层不再需要。

## 关联裁决

- `/ws/master` 幻影路由(handler 全仓不存在):其历史动机已由本档四项
  + 已建成的两个"算力插座"(声明式提供商注册表、NATS worker 网格,
  含面板 Mesh 区开关)完全覆盖 —— 该路由应择机拆除,不再承载任何规划。
- `core/galaxy_federation.py`(HTTP 联邦):维持 STRUCTURAL_ONLY 休眠,
  与本档选项 3 是不同物种(联邦=多权威中心;暖备=单权威主备),
  激活选项 3 时**不要**顺手激活联邦。
