# 真机验收清单：手机 + 手表 + 电脑

这份清单用来在真机上过一遍「三台设备当一个整体」。到 2026-10-25 为止，下面每一项都只在 CI 和模拟环境里验证过
（见 `SYSTEM_STATUS.md` 6.29–6.32），**还没有一项上过真机**。每一项写了怎么做、应该看到什么、不对时先看哪里。
过完一项就勾掉；没过的把现象记在项下面。

## 0. 准备

### 电脑（中心）

- 按 README 启动：`python main.py`（或 `python main.py --backend` 只起后端）。
- 云端 API 填进 `.env`。本地模型想用就拉起来（Ollama；实时语音的本地全模态服务 MiniCPM-o 可选）。
  两种都有时，系统按实际情况选：实时语音**本地服务在跑就用本地**，否则用云端。
- 先在同一个局域网里过这份清单；出门在外的连法（自建内网 tailnet）另测。

### 装 App（用 CI 打出来的 debug 包）

debug 包用 debug 签名，能直接安装。如果设备上装过别的签名的版本，先卸掉再装。

| 设备 | 从哪里下 | 怎么装 |
|---|---|---|
| 手机 | ufo-galaxy-android 对应 PR 的 Actions 运行 → Artifacts → `debug-apk` | 解压出 `app-debug.apk`，传到手机上点开安装（允许「安装未知应用」），或 `adb install -r app-debug.apk` |
| 手表 | galaxy-wearos 对应 PR 的 Actions 运行 → Artifacts → `wear-debug-apk` | 手表上打开 开发者选项 → ADB 调试 + 无线调试；电脑上 `adb pair <手表IP:配对端口>`（输入手表上显示的码）→ `adb connect <手表IP:端口>` → `adb -s <手表IP:端口> install -r app-debug.apk` |

### 配对

- [ ] 在电脑上跟智能体说「把我的手机接进来」。**应该**：它回一个 6 位配对码和一句「在那台设备的 Galaxy App 接入页输入配对码 ……」。
      想让手机出门也连得回来，可以接着说「手机也要能在外面连回来」，它会再给一条用 Tailscale App 进网的步骤（要了才给）。
      （6.32 之前这一步模型拿不到配对码，会说没成功或者编一个。）
- [ ] 手机 App 接入页输入配对码。**应该**：手机首页显示已连上；电脑上问「现在有哪些设备」能看到这台手机。
- [ ] 同样接手表（「把我的手表接进来」→ 手表上输入配对码）。手表首页显示「连着」。手表配对时自己声明要进自建内网，
      中心随配对发一把钥匙（出门直连靠它）。

## 1. 手机

首次打开会依次问权限：通知、麦克风是核心的；位置、通讯录、日历是可选的（不给也能用，只是对应的动作不报）。

- [ ] **设备卡跟着权限走**：电脑上问「我的手机能做什么」。**应该**：只列出给了权限的动作。去系统设置收回通讯录权限，回到 App，
      再问一次。**应该**：通讯录不在了。
- [ ] **位置**：「我手机现在在哪」→ 回坐标或地点；没给位置权限时说没给。
- [ ] **手机在兜里时的位置**：给了位置权限后打开一次 Galaxy，再锁屏放兜里，在电脑上问位置。**应该**：照样回位置
      （常驻服务在界面拉起时带上了 location 类型）。手机重启后没打开过 Galaxy 时问，**应该**说定不到位并说明原因 ——
      系统不许后台起的服务读位置，打开一次 App 就好。
- [ ] **日程**：「我今天下午有什么安排」→ 跟手机日历一致；空的就说没有。
- [ ] **通讯录**：「张三的电话多少」。
- [ ] **要人点一下才做的**：「给张三发短信说我晚点到」「打给张三」「明天下午三点加个会」。**应该**：手机上弹一条通知，
      点开后是系统短信 / 拨号 / 日历，内容已填好；**不点就什么都不会发生**（App 没有直接发短信、打电话、写日历的权限）。
- [ ] **打开应用**：「在手机上打开微信」。有悬浮窗权限时直接打开，没有时弹通知让你点。
- [ ] **截屏**：「看看我手机屏幕上是什么」。
- [ ] **跟智能体打电话**：手机 App 顶栏的电话按钮（连上中心时可点）。接通后说「帮我看看明天有什么安排」。
      **应该**：它边说话边去做，界面上出现「在做：…」→「做完了：…」，做完在电话里告诉你；挂断后才做完的，智能体自己决定发到哪台设备、怎么告诉你（看各设备的卡片），记下它选了哪台、合不合适。
- [ ] 通话中熄屏、切到别的 App，通话不断（前台服务）。

## 2. 手表

首次打开会问：通知、身体传感器（心率）、体能活动（步数）。后两个不给也能用，只是智能体读不到。

- [ ] **提醒**：电脑上说「在手表上提醒我喝水」。**应该**：手表弹通知；「震一下手表」→ 手表震。
- [ ] **状态**：「手表还有多少电」→ 电量、是否在充电。
- [ ] **心率**：戴着手表问「我现在心率多少」。**应该**：几秒后回每分钟多少下，和手表自带的心率读数相近。
      摘下手表再问。**应该**：说没测到（表没戴好），不编一个数。
- [ ] **息屏时的心率**：给了身体传感器权限后打开一次手表 App，再让手表息屏，在电脑上问心率。**应该**：照样测得到
      （常驻服务在 App 界面拉起时另带 health 类型）。手表重启后没打开过 App 时问，测不到是系统规则（后台起的服务读不了
      身体传感器），打开一次 App 就好。**这一项要特别看**：测不到就记下系统版本。
- [ ] **步数**：给了体能活动权限后走一段，问「我今天走了多少步」。**应该**：回步数和「从几点开始算的」。
      第二天走几步再问，**应该**从当天重新算。手表重启后再问，**应该**不归零（接着重启前的算）。
- [ ] **设备卡跟着权限走**：系统设置里收回身体传感器权限，回到手表 App，电脑上问「手表能做什么」。**应该**：心率不在了。
- [ ] **跟智能体打电话**：和手机那项一样，界面上显示交给智能体的事做到哪了；息屏时不显示这一行。
- [ ] **智能体问你**：让智能体做一件要确认的事（比如「把这个文件删了」）。**应该**：确认弹在手表上（手表声明了能回答提问）；
      手机上不弹（手机 App 还没有显示提问的界面，所以不声明）。

## 3. 三台一起

- [ ] **手表上问、手机上查、手表上答**：在手表上用语音问「我下午有什么安排」。**应该**：智能体去手机日历里查，答案回到手表上。
      手机的日历权限收回后再问。**应该**：手表上听到的是「手机上没给日历权限」这类原因，不是编出来的日程。
- [ ] **在手机上通话、让手表做事**：手机通话里说「在手表上提醒我五分钟后出门」。手表应该弹出提醒。
- [ ] **电脑上的实时语音也能做事**：电脑上开实时语音，说「看看我手机上今天有什么安排」。本地全模态服务在跑时用的是本地
      （后端日志里有「自动尝试本地全模态 server」），没跑时用云端；两种情况下它都应该去查、查完说结果。
- [ ] **状态由设备自己报**：电脑上问「我的设备现在怎么样」。**应该**：手机、手表的电量、充没充电、屏幕亮不亮跟设备上看到的一致；
      不说手机戴没戴着（手机不知道，不报）。手机开勿扰后再问，**应该**：说手机开着勿扰。设备断网后再问，**应该**：只说它不在线，
      不再拿它上次报的电量说事。
- [ ] **别打扰时不主动开口**：手机开勿扰（或手表报了别打扰），等智能体自己想起一件不急的事要说。**应该**：它不在任何设备上弹，
      后端日志里写着是哪台设备报的别打扰；你自己让它提醒的照常提醒。
- [ ] **开了设备准入时**（后端设 `GALAXY_REQUIRE_DEVICE_APPROVAL=1`）：一台没批准过的设备连上来，让智能体给它发一个动作。
      **应该**：说这台设备还没被批准，不发；批准后照常。

## 4. 手机端测：端到端与端侧开销

方法见 `docs/DEVICE_SELF_DESCRIPTION_DESIGN.md` 6.3。L1 定位、L2 单步动作在电脑上跑（安卓仓 `tools/eval/README.md`），
下面两层要真机。结果记进 `docs/eval/phone_gui.md`。

**L3 端到端**：在手机上直接说一句话，让手机本地循环从头做到底。每条记四样：成没成、走了几步、卡住几次
（logcat 里 `GALAXY:LOOP` 的 `stagnation_detected`）、做不了时有没有照实停下（而不是乱点）。凡是要花钱、要发出去的，只做到确认那一步。

- [ ] 打车：「叫一辆车去公司」（停在确认叫车那页）
- [ ] 点外卖：「点一杯美式」（停在付款前）
- [ ] 发消息：「微信跟张三说我晚点到」（字打进输入框，不点发送）
- [ ] 设闹钟：「明早七点叫我」
- [ ] 查天气：「今天要不要带伞」
- [ ] 导航：「去最近的地铁站怎么走」
- [ ] 改设置：「打开蓝牙」「亮度调低一点」
- [ ] 找照片：「找出昨天拍的照片」
- [ ] 查快递：「我的快递到哪了」
- [ ] 记事：「记一下，周五交报告」
- [ ] 看日程：「明天几点有会」
- [ ] 听歌：「放周杰伦的歌」
- [ ] 搜附近：「附近有什么咖啡店」
- [ ] 打开扫一扫：「打开支付宝扫一扫」（只打开）
- [ ] 计算：「用计算器算 37 乘 48」
- [ ] 打开相机：「打开相机切到前置」
- [ ] 没装的 App：让它在一个没装的 App 里做事。**应该**：说没装、停下，不乱点
- [ ] 做不到的：「把这页打印出来」（手机没连打印机）。**应该**：照实停下、说原因
- [ ] 中途叫停：做到一半说「停」。**应该**：马上停
- [ ] 断网：飞行模式下「明早七点叫我」。**应该**：照样做完（本地模型不靠网）

**端侧开销**：同一批用例，每个机型 × 每个端侧模型记一行。

- [ ] 每步时延：截图到动作发出（logcat 里 `GALAXY:LOOP` 每步的时间戳）
- [ ] 模型加载：App 冷启动后第一次规划等了多久
- [ ] 峰值内存：`adb shell top` 里 App 进程和 `libllama-server.so` 进程的 RES 峰值
- [ ] 连续跑 30 分钟：掉了多少电、机身多烫（`adb shell dumpsys battery` 里的 level 和 temperature）

## 不对时先看哪里

- 电脑：后端日志。设备有没有登记、报了哪些动作、命令发没发出去、回没回来，都在里面。
- 手机 / 手表：`adb logcat | grep -iE "galaxy|AgentCommand|PhoneCommand|VoiceCall"`。
- 智能体说「做不了」时，它说的原因就是设备回的原因（没给权限、没有传感器、表没戴好）。原因不对才是缺陷。
- 等了 30 秒才报超时 = 设备没回话：先看设备上那条命令收到没有。
