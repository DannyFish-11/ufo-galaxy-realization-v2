# Android Runtime-Profile Alignment Constitution v1

## 1) Purpose

This document defines Android-side constitutional alignment to the unified governed system constitution.

**Canonical companion target repository:** `DannyFish-11/ufo-galaxy-android`  
**Companion file expectation:** keep an equivalent constitution document in the Android repository with matching authority definitions.

## 2) Android role in the governed system

Android is a runtime-profile participant, not a parallel global authority:

- participates in delegated and cross-device execution
- reports capability/readiness/runtime continuity evidence
- follows center-governed dispatch, session, and truth authority outcomes

## 3) Android identity and continuity model

- Device identity remains registration/transport anchor.
- Runtime-host participation is attached to device identity but semantically distinct.
- Runtime attachment continuity (attach/reconnect) is distinct from conversation continuity.
- Delegation/transfer continuity is its own lifecycle and must preserve canonical terminal semantics.

## 4) Android and canonical planes

- Android contributes evidence to truth-governed decision paths.
- Android-facing read models are projections, not independent truth authority.
- Android compatibility mappings and adapters are migration surfaces, not canonical architecture endpoints.

## 5) Device domain and node domain alignment

Android participates in both related domains without collapsing them:

- **Device domain participation:** runtime hosting, transport, capability reporting, readiness participation.
- **Node domain participation:** delegated node/task execution and runtime-side execution contribution.

The two domains must remain explicitly distinct while interoperating through governed protocol contracts.

## 6) Canonical vs transitional alignment on Android

### Canonical

- center-governed orchestration and dispatch authority recognition
- canonical session/timeline semantics for control/runtime/transfer continuity
- canonical delegated execution/result/terminal vocabulary

### Transitional

- alias-normalized field names
- compatibility ingress families and bounded forward paths
- adapter-based bridging for pre-convergence contracts

Transitional paths are explicitly tolerated for convergence and must not overclaim canonical authority.
